# Universal Cooldown UI — **фикс Bloodcraft** для V Rising 1.1.x

**Это фикс для Bloodcraft, а не самостоятельный мод.** Он починяет связку перезарядки и
статов, которая сломалась при переходе игры с 1.1.12 на 1.1.15, и добавляет недостающий
интерфейс.

| | |
|---|---|
| **Чинит** | Bloodcraft **1.13.26** (собран под V Rising 1.1.12) |
| **Версии игры** | **V Rising 1.1.x** — разработано и проверено на **1.1.15**; на других сборках 1.1 должно работать, но не проверялось |
| **Требует** | BepInExPack V Rising (IL2CPP); серверной части нужны исходники Bloodcraft |

> Bloodcraft 1.13.26 собирался под V Rising 1.1.12. В 1.1.15 игра пересчитывает перезарядку
> из `AbilityBar_Shared` и атрибутов вампира, затирая всё, что записывает мод. Из-за этого
> восстановление перезарядки (CDR) не работало, а в описаниях оставались ванильные числа.
> Этот проект правит обе стороны.

---

## Что именно делает

### Серверная часть (патч Bloodcraft)

| Файл | Назначение |
|---|---|
| `Systems/CooldownRateService.cs` | Ставит реальное уменьшение перезарядки на каждую способность игрока (`AbilityCooldownData.Cooldown = ванильное × (1 − процент)`). Идемпотентно: значение всегда считается от префаба, поэтому при смене оружия ничего не накапливается. Плюс пишет файл синхронизации для клиента. |
| `Systems/BuffsTabService.cs` | Собирает, что Bloodcraft даёт этому игроку: постоянные баффы, синергии класса, бонусы крови, экспертизу оружия, — и пишет это клиенту, отдельный файл на игрока. |
| `Systems/StatsDiagnostics.cs` | Необязательная (`Enabled = false`) строка диагностики статов для настройки сервера. |

В Bloodcraft добавляются два маленьких хука (см. [`docs/SERVER.md`](docs/SERVER.md)):

- `Patches/ScriptSpawnServerPatch.cs` — после того как Bloodcraft применил баффы, вызвать
  `CooldownRateService.ApplyToPlayer(...)` и `BuffsTabService.Write(...)`;
- `Patches/StatChangeSystemPatch.cs` — `BuffsTabService.Tick()`, чтобы данные обновлялись и
  после кормления или смены класса, а не только при смене оружия.

### Клиентская часть (плагин BepInEx)

- **Описания способностей** — число перезарядки уменьшается на серверный процент
  (`Перезарядка: 8 сек` → `6,9 сек`).
- **Описание оружия** — синий блок с баффами Bloodcraft для текущего оружия
  (вампиризм, криты, скорость атаки и т.д.).
- **Вкладка Blood** — настоящая пятая вкладка в окне персонажа, сразу справа от «Атрибутов»:
  - **Общие** — постоянные баффы Bloodcraft (плащ, престиж-баффы);
  - **Класс: …** — синергии класса (какие статы класс поднимает и насколько);
  - **Кровь: …** — бонусы крови текущего типа;
  - **Оружие: …** — бонусы экспертизы оружия в руке.
- **Локализация** — английский и русский, язык определяется по системе.

## Установка — клиент

1. Установите BepInExPack V Rising в профиль мод-менеджера.
2. Положите `UniversalCooldownUI.dll` в `BepInEx/plugins/UniversalCooldownUI/`
   (или установите пакет из Thunderstore).
3. Запустите игру один раз — появится `BepInEx/config/universalcooldown.ui.cfg`.

Без серверной части плагин тоже работает: описания используют проценты из конфига, а
вкладка Blood показывает подсказку «данные загружаются».

## Установка — сервер

1. Возьмите исходники **Bloodcraft 1.13.26**, соответствующие версии игры.
2. Скопируйте `server/Bloodcraft/Systems/*.cs` в `Bloodcraft/Systems/`.
3. Примените два хука из [`docs/SERVER.md`](docs/SERVER.md) (по несколько строк).
4. Соберите и замените `BepInEx/plugins/<папка Bloodcraft>/Bloodcraft.dll`.
5. Перезапустите сервер (**только** через `start_server.bat`, иначе клиенты не подключатся).

Сервер пишет в `BepInEx/config` два вида файлов:

- `universalcooldown_rates.txt` — проценты перезарядки и статы оружия для описаний;
- `universalcooldown_buffs_<steamId>.txt` — содержимое вкладки Blood для конкретного игрока
  (плюс `universalcooldown_buffs.txt` для старых клиентов).

## Настройка (клиент)

`BepInEx/config/universalcooldown.ui.cfg`

| Ключ | По умолчанию | Значение |
|---|---|---|
| `General/Enabled` | `true` | Общий выключатель (описания + вкладка). |
| `General/Language` | `auto` | `auto`, `en` или `ru`. |
| `Tab/BloodTab` | `true` | Добавлять вкладку Blood в окно персонажа. |
| `Rates/Spell`, `Rates/Weapon`, `Rates/Ultimate` | `0.14` / `0.21` / `0.14` | Проценты, если файла сервера нет. |
| `Sync/RatesFile` | *(пусто)* | Путь к файлу процентов сервера. Пусто = `BepInEx/config/universalcooldown_rates.txt`. Данные вкладки читаются из той же папки. |
| `Debug/ProbeMenu` | `false` | Писать в лог структуру окна персонажа (после обновления игры). |

Если сервер на другой машине — укажите в `Sync/RatesFile` путь к синхронизированной копии файла.

## Как части общаются

Сервер и клиент не делят память — только текстовые файлы. Точные форматы — в
[`docs/PROTOCOL.md`](docs/PROTOCOL.md). Клиент получает нейтральные ключи (имена enum и
числа) и сам решает, как их показать по-английски или по-русски.

---

## Совместимость

- Работает вместе с **Raphael** и **Eclipse**: вкладка добавляется в ванильное окно, ничего
  не заменяя.
- Вкладка регистрируется в системе вкладок игры (`InventorySubMenu.TabButtons` / `Tabs`),
  поэтому подсветка и переключение остаются «родными».
- Затрагивается только окно персонажа; HUD, инвентарь и другие окна не меняются.

## Известные ограничения

- В Bloodcraft 1.13.26 **нет классовых пассивных баффов** — в самом upstream
  `ClassBuffMap` и `InitializeClassPassiveBuffs` закомментированы. Поэтому секция «Класс»
  показывает **синергии** класса (какие статы он поднимает), а не список пассивок.
- Вкладке Blood нужна серверная часть; без неё она показывает подсказку.
- Значения обновляются раз в несколько секунд (сервер перезаписывает файл только при изменениях).

## Сборка из исходников

Клиент (Windows, установленный BepInEx):

```powershell
dotnet build client/UniversalCooldownUI/UniversalCooldownUI.csproj -c Release `
  -p:BepInExRoot="C:\path\to\profile\BepInEx"
```

Проект ссылается на interop-сборки игры из этой папки, ничего в выход не копируется.

Сервер: скопируйте файлы в дерево Bloodcraft, примените хуки и соберите

```powershell
dotnet build Bloodcraft.csproj -c Release
```

## Публикация (Thunderstore)

Страница мода связана с этим репозиторием в двух местах:

- в метаданных пакета (`website_url`) указан этот репозиторий;
- `.github/workflows/publish.yml` автоматически загружает собранный релиз в Thunderstore.

Чтобы включить автозагрузку, добавьте секрет репозитория `THUNDERSTORE_TOKEN` (сервисный
токен команды Thunderstore) и опубликуйте GitHub-релиз с приложенным zip-архивом (собирается
`build-package.ps1`). Workflow отправит версию в сообщество `v-rising`.
